# S5 Achievements — карта

Версия на момент написания: 1.0.0 (16.11.2026). Факты по классам — `docs/INDEX.md`.

## 1. Что делает и чего не делает

Достижения сервера «Департамент S5» одной вкладкой: описания лежат файлами в `config/s5adv/`, перечитываются
без `/reload` всего сервера. **Только сервер** — клиенты получают достижения от него, ставить мод им не нужно.

За этим — не сюда:
- **когда** выдавать достижение — решает мод, в котором случилось событие: он зовёт
  `RpCoreAPI.grantAdvancement(игрок, id)` (ванильная выдача по id) и о существовании этого мода не знает;
- достижения других модов и датапаков — не трогаются.

## 2. Как течёт работа

**Загрузка.** старт сервера или `/reload` → ванильный `ServerAdvancementManager` загрузил достижения датапаков →
`mixin/ServerAdvancementManagerMixin` добавляет в готовый список наши: `AdvStore` читает
`config/s5adv/**.json` → id в пространстве имён `s5:` (`AdvStore.NS`).

**Перечитать.** `/s5adv reload` → `AdvStore.install` заново, через `ManagerAccess` (доступ к закрытым полям
менеджера), игрокам рассылаются обновлённые достижения.

**Выдать.** из игры — `/s5adv give|revoke`; из кода — любой мод через `RpCoreAPI.grantAdvancement` или этот мод
через `S5Advancements.grant / revoke / has` (обычная ванильная выдача всех критериев).

## 3. Карта пакетов

| Пакет | За что отвечает | С чего начать читать |
|---|---|---|
| `s5adv` | весь мод | `S5Adv` (вход), `AdvStore` (файлы → достижения), `S5Advancements` (API), `S5AdvCommand`, `ManagerAccess`, `SexCommand` (шуточная команда) |
| `mixin` | вставка своих достижений в менеджер ванили | `ServerAdvancementManagerMixin` |

## 4. Хочу добавить… — рецепты

| Что | Где | Образец | Не забыть |
|---|---|---|---|
| новое достижение | файл JSON в `config/s5adv/` на сервере, затем `/s5adv reload` | `docs/format.md` | кода не нужно; id — `s5:<путь файла>` |
| выдачу достижения из мода семейства | в том моде: `RpCoreAPI.grantAdvancement(игрок, new ResourceLocation("s5", "…"))` | RP Medicine `VanillaEffects.spinAchievement` | этот мод не импортировать и не искать отражением |
| подкоманду | `S5AdvCommand` | `list` | права 2 |
| поле в формате файла | `AdvStore` (разбор) | — | `docs/format.md` обновить |

## 5. Данные

| Что | Где хранится | Ключ | Что при смерти | Как попадает клиенту |
|---|---|---|---|---|
| описания достижений | сервер, `config/s5adv/**.json` | путь файла → id `s5:…` | — | ванильной синхронизацией достижений |
| полученные игроком | ванильный файл достижений игрока | id | остаются | ванильно |
| счётчик шуточной команды | игрок, `getPersistentData` | — | теряется | — |

Пространство имён `s5` и id выданных достижений не менять: они в файлах игроков.

## 6. Связи

Ни от чего не зависит и никем не импортируется. Моды семейства выдают достижения через RP Core по id.

## 7. Конфиги

`ForgeConfigSpec` нет: содержимое — файлы в `config/s5adv/`. Формат — `docs/format.md`.

## 8. Сеть

Своей нет: достижения уходят клиентам ванильными пакетами.

## 9. Ловушки

- **Мод работает с закрытыми полями ванильного менеджера достижений** (`ManagerAccess` + миксин): при смене
  версии Forge проверить, что поля на месте.
- **Клиенту мод не нужен** — и не должен появиться: всё, что видит игрок, приходит с сервера.
- Достижение без такого id на сервере `RpCoreAPI.grantAdvancement` не выдаёт и один раз пишет об этом в лог.

## 10. Тесты

Игровых тестов нет. `python ../_family/family.py verify "S5 Achievements"` — компиляция.
